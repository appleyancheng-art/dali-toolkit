## 安装与启动

目前在 Windows、Python 3.12 上验证。依赖固定到本次已运行的版本。

```powershell
cd mcp
.\install.ps1 -Python python
Copy-Item config.example.json config.json
```

示例配置不预填网关IP、本机IP或MAC，启动后处于未选定状态。新项目先搜索当前局域网，再按返回身份选定连接；不需要先知道IP。默认存储写入关闭；不要仅为解决报错而解除身份校验或开放写入。

```powershell
.\.venv\Scripts\python.exe run_server.py --config config.json
```

客户端注册时使用上面 Python、服务脚本及配置的绝对路径，transport 为 stdio。两份 Skill 可分别安装到所用 Codex 的技能目录；Computer Use 路线还需要当前环境提供可用的 Windows UI 工具。它不依赖 MCP 来代替界面操作。

普通命令也可通过标准 MCP CLI 执行：

```powershell
.\.venv\Scripts\python.exe client.py --config config.json --tool dali_status --output status-check.json
```

参数从 JSON 文件传入 `--arguments`。输出文件须是新路径，防止无意重复执行。CLI 不自动启用写入、不重发控制命令；场景保存和参数批量start任务会保持服务器存活并轮询到终态；强制退出或连接失败仍可能留下部分修改，核对原计划后再处理，不自动重发。

CLI预检服务、配置、参数文件及输出路径。错误默认显示简短提示，`--debug`才输出完整Python堆栈；错误记录仍保留完整工具响应和嵌套原因。正常stdout为JSON摘要，包含tool/state以及适用的rows_count、layouts_count、results_count和result_status_counts；退出码0为客户端正常且未发现已定义失败状态，2表示错误/不成功结果，130表示用户中断。摘要中的returned不等于设备验证成功。`dali_status`仅回显本地配置，connectivity=not_checked、network_traffic=false，不能作为网关在线证明。

客户端日志的`client_error`表示调用端失败，不等于设备没有变化。`failure_phase=connecting`且`request_intent_count=0`表示尚未准备任何工具请求；`calling_tool`的pending只表示已记录请求意图，不能证明已发送或已执行。调用关闭阶段失败仍保留已收到的result和calls，不能据此重发。保存任务查询出错时保留原job_id，先查原记录；不换ID重做。`returned`仅表示客户端正常返回，设备操作是否成功仍看result中的state和验证字段。若磁盘同时拒绝保存错误日志，原异常保留并附注日志错误；旧记录不能据此判定进程仍活着。

场景保存/应用的results[].status契约：verified表示写入后读回符合；unchanged表示新读原值已符合、成功跳过写入；outcome_unknown表示结果尚未验证；verification_failed表示读回不符。整批成功须同时满足state=completed、结果数等于全部请求目标且每项为verified或unchanged。部分终态、缺失项和未知结果不可当作成功，也不可盲目重发。已确认效果并授权保存时优先dali_save_scene_batch，避免不必要的preview+apply重复预检；需要单独审阅差异时才拆开。保存/保存作业/差异预览每次最多1024个明确地址/场景组合，支持64灯×6场景=384项的一体化作业；读取场景和工程场景恢复预览仍限64对。allowed_write_targets兼容单对象或独立范围对象列表，空列表拒绝全部写入。每项包含channel、scene、addresses，彼此不构成交叉授权。配置开关不替代用户授权。

色温在已验证DT8设备上按整数mired量化：mired=1000000//requested_K，典型读回K=1000000//mired。例如3000→3003、3500→3508、4000→4000；边界/钳位仍取决于灯具。判断等效时先排除MASK等哨兵值，再比较1000000//requested_K与1000000//actual_K。独立读取不知道历史请求，不能凭读回伪造requested_kelvin。原始65535是场景MASK，不代入此公式。

保存任务使用持久化 request_id 防重复，取消在灯具操作之间生效，已发写入仍完成读回，不自动回滚。stdio进程退出会中断任务；重启标记 interrupted，不自动续写。同一状态目录只有一个任务进程所有者，但没有与上位机共享的跨程序锁。

网关回执只表示接收；检查 `receipt_status`、`verification_status` 和读回结果。抽查不能宣称全灯逐一通过。超时先核对现场，不盲目重发。

## 百分比与图案准备

优先用 `dali_prepare_live_output(channel,changes,scene?)` 把每灯 `percent` 与可选 `kelvin_raw` 转为原始目标。它只读设备能力，不点灯、不保存；返回 `live_arguments` 可交给 `dali_set_live_output`。非零百分比只支持已确认的标准对数曲线0，并核对配置亮度上下限；0是OFF，低于0.1%的非零值、其他曲线及越界值会拒绝，不静默截断。量化百分比不是实测照度。换灯或改参数后刷新 profiles，包括亮度限制。

编排图案先 `dali_get_layout` 查项目布局；无合适记录时，用用户已明确的地址矩阵调用 `dali_create_layout`。矩阵每行从左到右、各行从上到下，null为空位，地址不可重复；记录绑定当前配置网关与固件。它不会自动辨认实物排列，换项目不能硬套旧布局。

`dali_compose_layout_output` 接受布局ID、foreground_percent、可选色温、8×8内置glyph X/M/N/B，或自定义同尺寸0/1字符串行；glyph与pattern_rows二选一。background必须明确：off生成图案外已映射灯具的OFF目标，preserve省略背景。根据用户意图选择，不扩大到未映射地址；输出列出前景、背景及不操作地址。内置字形是当前模板，不保证与历史手工保存图案完全相同。

准备后按用户授权执行 live_arguments、检查预览效果，再按保存请求存储。可选scene直接传0～15；返回scene_changes只是目标清单，不是捕获当前输出，不会保存。省略的分量在场景中成为MASK（亮度255、色温65535），表示调用时保持。若用户要求保存实际当前效果，应核对当前值或最近已验证预览结果，不能把未知实时值当成这些目标。准备结果中的样本地址不等于全板验证，也不自动切换成广播。

全关场景无需绕过准备接口。例如 `{"channel":2,"changes":[{"address":0,"percent":0}],"scene":1}` 生成实时目标level_raw=0（不发色温），同时生成场景目标level_raw=0/kelvin_raw=65535。全64灯须明确列出0～63。准备输入省略色温，不能传65535：它是场景存储MASK而不是有效的实时色温。布局是现场资料，安装包故意不包含旧state；0.14提供单独布局导入导出与人工核对记录，0.17支持显式附到工程新修订。

独立现场日志的整通道双参数示例：首次服务总耗时82.016秒，其中预检75.235秒；热缓存7.031秒。另起会话全64实时读取25.749/25.881秒。仅作特定设备的量级参考，不承诺每次速度。实时预检目前没有CLI阶段进度，保持足够超时（默认单调用300秒），超时后先查记录；禁止用并发查询替代串行预检，此网关曾出现并发读丢结果。

## 工程快照、差异与场景恢复

`dali_capture_project(name,channel,addresses,scenes)` 串行新读指定1～64地址的已支持参数（含分组）和指定0～15场景，最多64×16项场景。它不搜索、不修改地址，不点灯。采集不是原子快照，记录各字段时间；当前未覆盖物理CT极限、扩展渐变、设备版本、PC备注/工程文件、网关设置、布局或实时输出。全通道全场景可能数分钟，保持stdio进程及连接；CLI可用 `--timeout-seconds 1800`。超时后先查记录，不自动重采。

`dali_get_project()` 列最近记录及pending；传project_id返回完整JSON，可保存为工程导出。读取记录不等待总线锁，但reading只表示最后保存的阶段，不能证明原进程存活。stopped_partial保留已采集字段和失败位置；不能用于导入、差异或恢复。没有记录不等于空工程。

`dali_import_project(document)` 只把完整工具包JSON导入为一个新的本地记录，不连接文件内的IP、不恢复设备。校验和用于发现意外损坏，不验证来源真实性；导入标为来源未验证。它不兼容上位机原生工程格式。导出包含网关和现场配置，只随用户指定的交付范围分享。

`dali_diff_projects(before_id,after_id)` 比较同网关IP/MAC/固件和同通道的精确参数与场景值；忽略读取时间、回执封装以及DT6无定义的色温字节。范围不同会给出not_captured_before/after，不能把缺项当成0、离线或删除要求。差异本身不授权改设备。

用户要求恢复时，用 `dali_preview_project_scene_restore(project_id,addresses,scenes)` 明确选择已采集的1～64个地址/场景组合。它新读能力限制与当前原值，生成现有的10分钟场景计划；仅支持同配置网关的DT8场景存储。原工程中超出现灯具限制的值会拒绝，不截断。取得用户对该范围的恢复授权后，使用已有dali_apply_scene_batch及任务专用写入范围；保持原值备份、写前冲突检查和写后逐灯读回。不会恢复参数、组成员、地址、标签、网关设置或实时灯光。用户已明确要求恢复的范围无需再次重复询问。

`dali_preview_project_group_restore(project_id,addresses,group_numbers)` 则只恢复明确地址及组号的成员位，其他当前成员保持不变。它要求完整工具包工程、同网关/固件/灯类型，重新读取成员与实时状态；全部匹配时返回already_matches、不生成执行计划。有差异时生成现有10分钟组计划，使用独立组写开关和精确操作范围授权后应用；写前任何组位或灯光漂移均会停止。源工程摘要和选择范围保存在计划内并重新验证，不接受原生缓存占位值。撤回本次恢复使用dali_prepare_group_restore，恢复本次操作前值。多地址写入和DT6仅模拟验证；不扩大为参数、地址或原生工程的整体恢复。

导出完整项目JSON后，可以离线生成中文摘要：

```powershell
.\.venv\Scripts\python.exe project_report.py --input project.json --output project-summary.txt
```

摘要保留原始值，区分关闭与MASK，不把存储场景当作当前输出；不连接设备。

## 验证与边界

`install.ps1` 只运行本地模拟网关测试及离线 stdio 检查，不扫描或控制真实设备。显式只读现场检查：

```powershell
.\.venv\Scripts\python.exe tests\smoke_stdio.py --live --config config.json --channel 2 --addresses 0 63
```

现有地址扫描用固定只读模式，最长可能约4分钟；成功返回本次网关扫描位图，超时/错误返回scan_unknown，不能解释成空通道。组查询返回所请求短地址的成员组，部分地址结果不能代表完整组成员。只读查询不诊断地址冲突和详细灯具故障。

组成员写入与恢复已接入，现场限单地址/组15试验；工程中的选定组位恢复和参数候选另有各自验证范围。参数写入开放单灯渐变时间/速率、亮度/色温上下限及上电/故障亮度；单灯改到空闲地址见0.34，其余寻址、复位、升级、完整原生工程恢复仍未实现；上位机名称文件回写使用独立0.22事务。原生缓存读取/名称草稿、工具包JSON工程、选定场景与组位恢复计划、选定参数只读恢复预览已支持。DT6和其他固件未实灯验收。具体证据和未完成项见 [验收记录](docs/VALIDATION.md)。

`dali_read_lamp_parameters` 每次1～16地址，按字段保留新鲜读回和时间戳：类型、状态原始值、渐变代码、亮度上下限、上电/故障参数、曲线、配置色温上下限、组成员。失败返回具体待处理字段及部分结果，未知不填0。它不测试掉电/故障行为，不包含物理CT极限、扩展渐变或版本，不刷新独立能力缓存；实时值与场景仍由各自工具读取。

本包不含厂家可执行文件、对象文件、安装包、用户网关配置和现场日志。本包用于私有仓库交付，未附开源许可证；不包含厂家程序的再分发授权。

## 组成员与名称流程

组成员变更先prepare，changes每项含address/add/remove；组号0～15。核对差异后按已授权范围启用任务配置enable_experimental_group_writes，allowed_group_write_operations逐项包含channel/address/group/member。member是布尔值，false移出。用计划确认串apply，一次性声明阻止重复执行；get可在执行中读取持久化阶段，但阶段不是进程存活证明。失败后不重发；restore先新读并生成独立计划，只恢复有原值和已尝试记录支持的差异。详情见MCP Skill。

原生缓存导入只接受已观察的ConfigMaster1.2.4.1单网关JSON，核对服务配置IP/MAC/固件，不连接文件指定地址。名称草稿按channel/address或channel/group/scene定位，最多30UTF8字节，超长拒绝而不截断。rebase接收调用者提供的当前JSON，保留无关更新、拒绝同一名称的并发变化；draft_ready不是已应用，也不证明源文件仍未变化。完整JSON导出可能含项目信息，按用户指定范围分享。

0.12原亮状态找灯现场补验：通道B地址0临时设置raw229后，独立读取64地址确认仅该灯亮度改变、全部色温保持。找灯工具依次发送raw0、254、229，13.969秒完成，回执、各阶段读回和原亮度/色温恢复均通过；随后再读取64地址，全部与找灯前点亮状态一致。最后仅将地址0关闭，再读64地址，全部亮度/色温与最初全关基线一致。没有场景、参数、分组或色温写入；异常分支仍为模拟验证，不表示现场故障注入通过。

## 0.14 工作流补充

多场景任务保持同一stdio进程，按原request_id查询，progress.scenes给出各场景备份/完成/尝试数。所有目标备份完成后才开始写入，取消不回滚，未知结果不重发。大批次仍串行，会受备份和逐项读回耗时影响，尚未进行384项实灯测速。

dali_preview_scene_restore仅新读终态计划中已尝试写过的目标；当前值若不同于原值和尝试值则restore_conflict。它不恢复灯光、不写设备；只有明确授权恢复才应用新计划，未尝试和unchanged目标不纳入恢复。对仍在执行/遗留applying的计划不猜测进程状态。

布局通过dali_export_layout/dali_import_layout单独交接；包含网关身份，分享前确认范围。导入同身份数据生成新ID并重置现场核对标记。dali_record_layout_check只记录真实人工核对，是human_attestation，不是自动物理验证；返回新修订ID并保留原记录。它不是上位机原生平面图；0.17可按下节显式附到工具包工程新修订。

dali_get_live_operation读取实时操作保存的预检、发送及样本结果，不等待总线锁。单灯批量和广播预检记录pending_address、completed/total和cache/bus来源；组操作已有pending阶段。应在原长连接查询，不能用第二个服务器抢占同状态目录。存盘状态不证明进程存活；长时间等待也不是重新发送控制的理由。

## 0.15 渐变时间专用事务

dali_prepare_fade_time新读一盏DT8灯的全部已支持参数/实时输出并生成10分钟计划，fade_time_code仅1～15原始码（不是秒数），不支持code0/扩展渐变原值或目标。dali_apply_fade_time只允许fade_time字段，默认禁用，需用户明确授权及单独配置：

```json
{"enable_experimental_parameter_writes":true,"allowed_parameter_write_targets":{"channel":2,"address":0,"values":[{"field":"fade_time","values":{"code":5}}]}}
```

示例仅展示格式，不是通用授权。限定为当次任务，结束关闭；不修改常驻默认开关。原值变化会在写前拒绝；一次性claim防止重放；回执未知后只读状态，不重新写。completed_readback只代表范围内存储/参数读回，不证明实际渐变时长。其他字段参数计划会拒绝，不能用此接口绕过未开放的写入范围。

dali_get_fade_time_plan读取计划/声明/执行，缺失执行记录仍不确定。已授权恢复时用dali_prepare_fade_time_restore生成新计划，把允许值改为原code再应用；其他配置改变或状态冲突就停止，already_original无需写入。没有自动回滚或自动恢复进程。

现场仅验证B0时间码4→5→4、速率码7保持，全部已支持参数恢复；前后64灯亮度/色温逐一一致且全关。未发送点灯或场景/分组/地址命令。其他代码、设备及故障路径主要为模拟测试。

## 0.15.1 实时操作进度通知

指定灯具、整通道和整组实时输出通过标准MCP进度回调推送已保存的操作记录，无需第二个客户端或额外总线查询。CLI默认显示event=progress，并在--output记录累计条数及最近128条通知；最终完整结果仍由原工具返回。订阅者缓慢时合并到最新记录，失败不打断物理操作、不重发；网络通知不能当作设备到位证明。

通知的外层progress是递增通知序号，没有总百分比；message是包含kind、operation_id、state、progress阶段计数的JSON。阶段内计数可重新开始。缓存能力、渐变等待、发送和读回有各自语义，不能把通知100误读为完成100%。中断后用原operation_id核查已保存记录，别换新请求重试。

该修订只改善可观察性，不宣称现场控制提速。维护和独立包离线测试、标准SDK通知传输分别验收；64目标对照测试确认总线调用序列不变。此处为0.15.1历史范围；色温下限等待回执问题已在0.17.1修复，0.18开放受限接口。

## 单灯参数写入与恢复（0.19）

`dali_prepare_lamp_parameter(channel,address,field,value)` 新读一盏DT8灯的全部已支持参数和实时输出，准备一个参数的10分钟计划，不写设备。field/value范围如下：fade_time、fade_rate用原始code1～15，min_level、max_level用原始亮度1～254，configured_min_ct、configured_max_ct用Kelvin1000～10000，power_on、system_failure用原始亮度0～254。不是百分比或秒数。上电/故障字段仅改亮度，原色温含65535均保持；本接口不能修改配对色温，原亮度255目前拒绝，以免生成不能恢复的计划。旧fade_time接口仍只接受渐变时间。

`dali_prepare_power_parameter(channel,address,field,level_raw?,kelvin_raw?)`准备一个上电或故障参数对，field只能是power_on或system_failure。至少提供一个分量：level_raw为0～254原始亮度，kelvin_raw为配置范围内1000～10000K或原始MASK值65535；省略/null的分量保持刚读出的原值，两个分量也可同时修改。不改变实时输出，不代表已实际断电或触发故障。原亮度255仍拒绝；原有限色温若落在当前配置范围外也拒绝，以免生成无法恢复的计划。使用同一套dali_apply_lamp_parameter/get/restore接口，执行范围必须包含合并后的完整亮度、色温对；只授权kelvin_raw而漏掉随包保留的亮度会拒绝。完整目标见proposal.steps[].after。

原值和目标都须可恢复，最小/最大值保持有序。普通色温限制计划只允许在当前配置范围内缩小；不能用配置限值冒充物理能力并向外扩展。恢复计划可以基于原执行计划的原范围证据恢复该次修改，移除/篡改恢复关联不能绕过检查。Kelvin请求值与量化读回值分别保留；不把原始2702K擅自取整成2700K写入。

按用户已授权范围，任务专用配置启用`enable_experimental_parameter_writes=true`，并将`allowed_parameter_write_targets={channel,address,values:[{field,values:完整目标值}]}`限定到计划`proposal.steps[].after`。例如上电亮度目标必须包含`{level_raw:2,kelvin_raw:65535}`这两个实际分量；只允许亮度而未声明随包保留的色温会拒绝。色温限制用`{kelvin_raw:3003}`，渐变用`{code:6}`。这些只是格式例子，应以本次计划为准。把plan_id和confirmation交给`dali_apply_lamp_parameter`；既有修改/恢复授权无需再问，结束关闭任务开关，不改变常驻默认值。

执行前核对身份、原参数和实时输出，落盘一次性声明及写意图；单次发送后完整读回并使目标地址能力缓存失效。色温、上电/故障的状态0表示保存进行中，服务等待末次回执再查询。completed_readback仅证明本次存储/输出读回，不证明实际渐变时长、断电或故障行为。丢回执只读协调，stopped_receipt_unknown即使读值符合也保留不确定，不重放。限制修改导致实时输出改变时停止，不自动补发点灯命令。

`dali_get_lamp_parameter_plan(plan_id?)`只读本地记录，不占总线锁；缺失执行记录或保存的中间状态不证明进程存活，也不是重试许可。`dali_prepare_lamp_parameter_restore(plan_id)`新读后准备仅原字段恢复；任一配对分量的第三值、无关参数改变或多字段祖先会拒绝，already_original无需写入。恢复使用新计划和精确原值范围，不自动恢复意外改变的实时输出。

## 工程随附布局（0.17）

需要把地址排列随工程交付时，先有完整工具包工程和明确布局，再用`dali_attach_project_layouts(project_id,layout_ids)`选择1～16个本地布局。它不读总线、不重新采集参数；创建新的schema2工程修订，保持原采集参数、场景和时间，嵌入完整布局快照。网关IP/MAC/固件和通道须一致，布局地址必须全部在工程已采集范围内。不能为容纳布局自动扩大采集或恢复范围。

layout_ids是新修订包含的完整列表，会替代该新修订中的旧随附列表；源工程和本地布局均不覆盖。`dali_get_project`导出完整JSON，`dali_import_project`能在另一目录导入schema1/2工程。原来的人工核对声明保留为来源证据，`layout_context`明确不是当前现场已核对；导入工程不会自动安装可用于控制的布局。校验和只证明数据一致性，不认证来源。

确认要使用其中某个排列时，以工程内的source_layout_id调用`dali_import_project_layout(project_id,source_layout_id)`。返回layout中的新layout_id才是本地可用映射，physical_mapping_verified=false、不继承mapping_check；原项目核对记录仍保留在工程内。当前配置网关不匹配时拒绝提取，不能直接把旧现场排列套给新现场。需要实际核对时沿用dali_record_layout_check，仅记录用户或操作员确实完成的检查。

`dali_diff_projects`的layout_comparison另列来源名称/几何排列差异；缺少布局是not_captured，不等于空布局或删除要求。参数/场景differences仍按采集值比较。离线project_report.py会输出地址矩阵、空位和来源声明。新格式仍不是上位机原生工程/平面图，也不会恢复地址、成员、场景或实时灯光；旧版仅支持schema1的客户端会拒绝schema2，不能直接删字段冒充兼容。


## 上位机名称文件事务

用户要求直接保存上位机本地名称时，用0.22的文件事务，不能把草稿生成说成已改名。将经核对的**单网关名称缓存文件**绝对路径配置为 `configmaster_cache_file`，不用参数缓存或任意JSON；`dali_read_configmaster_file()` 从实际文件新读并返回文件SHA256、缓存ID和名称来源。该工具不读取设备或上位机内存，磁盘内容也不是灯具实时状态。

准备/写入/恢复要求Windows上所有ConfigMaster进程已退出。先处理用户原有未保存编辑，不擅自丢弃；服务只检查进程，不会自行强杀或启动上位机。关闭后 `dali_prepare_configmaster_file_names(changes)` 按既有kind/channel/address/group/scene/name格式生成10分钟计划，保留原始字节备份与精确名称差异。仅修改明确要求的标签，地址/场景号仍0起始。

在已获授权的任务配置中单独设置 `enable_native_cache_writes=true`，调用 `dali_apply_configmaster_file_names(plan_id,confirmation)`。它只操作绑定文件，不发网关命令；写前再次检查文件SHA256和进程，原生替换后逐字节读回。`written_verified`仅证明文件符合目标，重开上位机后还须核对显示。工具间的路径锁不阻止上位机或其他编辑器启动，执行期间保持它们关闭。不要通过改计划或删claim重试；每份计划只尝试一次。

`dali_get_configmaster_file_plan(plan_id)` 查备份摘要、claim和执行记录；saved phase不代表进程仍活着。`write_uncertain`、日志不完整或替换异常时先读文件和原记录，不重放。已授权撤销或测试包含恢复时，关闭上位机后调用 `dali_prepare_configmaster_file_restore(original_plan_id)`，再应用返回的新计划。它仅撤销实际改变的名称，目标已改成第三个值则整份拒绝；保留其他新数据和其他新名称，缺失与空标签不混为一谈。文件未发生其他变化时恢复原始字节；有无关变化则重建仅名称逆变更。`already_restored`不需要写入。任务完成关闭专用写开关。

PC1.2.4.1实际缓存已验证B0、组15及组0场景5三种名称：写入后完整重启，上位机树和批量页显示新名称；关闭、恢复后再次完整重启，空灯名/无组备注/原场景备注均正确。写入与恢复期间其他文件字段及独立参数缓存未变；上位机自行刷新的缓存字段保留。此能力不修改DALI场景、地址、分组成员或网关设置，不代表原生完整工程恢复。
