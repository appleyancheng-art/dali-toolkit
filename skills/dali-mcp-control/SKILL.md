# DALI MCP 调试

通过已配置的 DALI MCP 工具执行操作。先发现当前可用工具并核对网关身份、固件、通道和目标范围；不要将另一套 KNX HTTP 网关接口当作本协议。服务版本以dali_status返回为准，历史归档保留；现场设备验证限于指定网关固件 1.6.9 的 DT8 灯具。新接口是否可用以当前工具列表为准。dali_status只读本地配置，connectivity=not_checked不证明设备在线。

## 网关连接

新项目、不知道IP、原网关换IP或要切换网关时，优先读[网关搜索与连接](references/gateway-connection.md)，先搜索并选定当前项目网关，再查询灯具或调光；不要沿用上个项目的固定IP。0.40起支持无固定IP启动、广播搜索、明确选定后连接，跨项目应使用已修正变长名称解析的0.41及以后版本。旧`dali_discover`仍只查询当前配置IP，不能当作LAN搜索。多个网关按项目身份选择，后台任务运行中不切换。

用户已明确当前项目及选定目标时，可沿该选择执行查询，由服务重新核对实际网关身份；新开一个stdio进程不等于换项目。配置文件或本地selected本身不证明在线，也不能替代新项目的搜索与选定。

需要给新接入的无地址灯具编址时，读 [新增地址流程](references/address-allocation.md)。仅用于实际提供新接口的0.39及以后版本；已知测试板B63新增闭环已验证，预计数量仍不限制设备侧分配范围。普通调灯、场景保存不需要寻址。

## 目标与数据

- 通道参数 1=A、2=B；短地址 0～63，组号 0～15，场景 0～15。用户说场景 8 就传 8，不减一。不同通道的同号地址不是同一盏灯。
- 类型、亮度和色温上下限、曲线及渐变时间缓存刷新用 `dali_read_lamp_profiles`。其缓存有效期 24 小时，绑定网关身份；换灯或修改能力参数后刷新。实时输出和场景值以总线读回为准。
- 原始亮度 0=关，254=100%，255=场景 MASK；不是线性百分数。仅在确认标准对数曲线后，非零百分比 p 换算为 round(1+253/3*(log10(p)+1))，并限制在 1～254。报告必要的量化差异，上位机显示百分数可能有舍入差异。
- 色温 65535=场景 MASK，不能当成关灯。请求超出设备范围时说明限制，不擅自改写设备上下限。色温采用设备 mired 档位量化，保留请求值和读回值。
- 物理布局是项目数据，不是协议默认值。当前测试板是 8×8、左上为 0、每列从上到下再向右，address=8*column+row。换项目必须重新确认布局，不硬套这块板。

## 现有地址与分组只读查询

用户问通道有哪些灯，使用 `dali_scan_existing(channel)` 获取本次网关扫描出的现有短地址。固定搜索模式不分配或修改地址，不改变灯光；最长可能等待约4分钟。只有 `state=completed` 才能使用 `addresses/count`；`scan_unknown` 表示未取得可信结果，不能说全离线或空通道，也不自动重复扫描。该清单不诊断地址冲突、故障状态或灯类型；需要类型和能力再对发现的地址读 profiles。

用户问所属组或组成员，使用 `dali_read_groups(channel,addresses)`。每行 `groups` 是该短地址所属的0～15组。只查部分地址时，结果不能代表某组完整成员；要报告完整通道组成员，需先取得地址清单再读其全部地址，并说明扫描时点。`stopped_partial` 保留已读行及 `pending_address`，未读/失败地址不是“不属于任何组”。编辑成员使用 [分组计划流程](references/live-groups.md)。按组实时输出已在当前DT8测试板的组1完成现场验收。

## 操作顺序

用户要求找灯时，用 `dali_identify_lamp(channel,address,hold_seconds=2)`，一次只针对一个明确短地址。它先确认稳定原值和已知短渐变；原色温未知或为哨兵时在控制前拒绝。原来亮着则短暗一次，再到配置最大亮度，最后恢复原亮度；每个到位阶段保持1～5秒。不改色温、场景、分组或渐变设置，不等于上位机的专用爆闪/慢闪命令。检查 `restore_verified`、`brightness_restored`、`kelvin_unchanged`，不要只看回执。`stopped_restored`表示找灯中途异常但恢复已读回；`restore_unverified`表示可能仍有变化，先读实时值。保持stdio进程到返回，强制退出无法保证恢复；用 `dali_get_identification()` 找最近记录及原值，指定operation_id可取完整记录。保存的中间阶段不证明原进程仍在运行，不盲目再调用找灯或自动重播记录。

0.12原亮状态找灯现场补验：通道B地址0临时设置raw229后，独立读取64地址确认仅该灯亮度改变、全部色温保持。找灯工具依次发送raw0、254、229，13.969秒完成，回执、各阶段读回和原亮度/色温恢复均通过；随后再读取64地址，全部与找灯前点亮状态一致。最后仅将地址0关闭，再读64地址，全部亮度/色温与最初全关基线一致。没有场景、参数、分组或色温写入；异常分支仍为模拟验证，不表示现场故障注入通过。

1. 用户要求设计或调整效果时，先实时预览。指定灯具使用 `dali_set_live_output`，changes与verify_addresses都必填，后者为目标中的1～8个样本，省略亮度或色温分量表示保持；只有明确授权整通道全部地址相同设置时才用 `dali_set_channel_live_output`。形状外灯具需关闭时，按明确全板范围处理。
2. 不为预览而先写入场景再调用。亮度可能打断色温渐变，保留服务中的色温到位检查及广播渐变等待；不自行并发发送报文。
3. 看 `samples_verified` 和实际读回，而不只看网关回执。样本验证不能描述成全部灯具逐一验证。
4. 用户确认效果并要求保存时，优先 `dali_save_scene_batch`，只包含明确目标；它备份原值、跳过等效未变化项、写后读回。需先审阅差异时才使用 `dali_preview_scene_batch`、`dali_get_scene_plan`、`dali_apply_scene_batch`。
5. 默认存储写入关闭。用户已授权保存时，可建立任务专用配置，启用写入并限制 `allowed_write_targets` 到指定通道、场景和地址，完成或异常退出后关闭。配置开关不是用户授权替代品，不因调试报错任意开放。
6. 仅调整既有场景部分灯的色温时，可以只更新这些灯；保存完整新图形时，必须包含需关闭的背景灯，防止残留旧图形。原值备份和核对仍由服务执行。
7. 调用整通道已存场景用 `dali_recall_scene`，不能用它冒充单灯或组调用。单灯调用用0.42起的 `dali_recall_lamp_scene`，具体边界见 [场景与布局](references/scenes-layouts.md)；按组调用见 [实时与分组](references/live-groups.md)。调用会改变实时灯光，不改场景存储。

## 错误和当前边界

- 场景结果verified与unchanged都是成功项，后者表示新读原值已符合而跳过写入。整批还须state=completed且结果覆盖全部请求；outcome_unknown、verification_failed及缺失项不是成功。不能按“非verified即失败”误判后自动重做。
- 准备全关场景时传percent=0并省略kelvin_raw，指定scene；准备结果的实时目标不含色温，场景目标自动含色温MASK65535。不要把65535传入实时色温参数。色温3000K可能读回3003K、3500K可能3508K；非哨兵有效值按1000000//K比较mired等效，不直接要求开尔文整数相同。独立读取没有原请求上下文。
- 每个任务留存意图、目标、结果和原值。超时、部分失败或状态未知时停止，不盲目重发；先 `dali_read_actual` 或 `dali_read_scenes` 核对。
- 0.3.0 已修复非零场景回执不回显场景号导致的误报。分别看 receipt_status、verification_status 和 samples_verified：真实回执丢失但读回符合时仍保留 dispatch_error，不再调用。全 MASK 样本不能证明场景生效；verified_sample_count 表示实际可核对样本数量。
- MCP 与上位机不要同时修改同一总线。同一状态目录限制单个 MCP 服务进程，各事务还有相应串行或文件锁；这些锁不能约束上位机、其他电脑或使用其他状态目录的客户端。
- 已支持的地址、参数和工程操作以当前服务工具及对应流程为准。复位、固件升级、全新分配及完整原生工程恢复仍不在已验收范围；不得根据按钮名、反汇编符号或旧日志自行拼包执行未覆盖功能。
- MCP 工具在会话中未加载时，若本机已有经过核对的服务，可使用标准 MCP 客户端通过 stdio 连接；不要为每次操作重新实现 UDP。发现/状态工具用于检查，不把注册成功当作当前工具已加载。

## 本机服务未加载时

优先从当前客户端的 MCP 注册项定位 `dali_config`（名称可能由用户改过），读取该项的 `command`、`args` 和 `--config` 路径；不要猜用户名、IP或安装位置。在 Codex 本机可按环境指示定位配置文件，只查看相关 MCP 项，不输出其他凭据。确认入口属于本工具包后，可用标准 MCP SDK 的 stdio 客户端连接同一入口。若没有注册项，从用户已有工具包目录找 `mcp/run_server.py`、`mcp/client.py`、本地配置；示例配置里的地址和MAC不可直接连接现场。

客户端失败记录要区分阶段：`failure_phase=connecting`且`request_intent_count=0`表示没有准备工具请求；`pending`只记录意图，不能证明已发送或成功。关闭连接时报错会保留已收到的result/calls，不能因为client_error重发。保存任务轮询失败继续核对原job_id，不换ID重做；`returned`只表示客户端完成，仍检查设备结果的state/验证字段。日志本身保存失败时，异常附注说明，旧starting/reading记录不证明进程存活。

CLI默认显示简短错误，--debug显示堆栈；stdout摘要含tool/state与适用的rows_count/layouts_count/result_status_counts，完整证据仍读--output。历史首次整通道预检约75秒、热缓存整次约7秒，设备与环境不同会变化；0.14可用dali_get_live_operation查询阶段记录；0.15.1的CLI默认显示三种实时输出工具的MCP进度通知，并在输出JSON保留最近128条及累计条数。不要以短超时或并发请求提速，保持串行且不自动重发。

可复用 CLI：使用该服务配置的 Python 运行 `client.py --server <run_server.py绝对路径> --config <实际配置路径> --tool dali_status --output <新日志路径>`，先只读核对。后续工具参数写入JSON文件，通过 `--arguments <文件>` 传入。不要手写新的UDP客户端。原始开发目录的入口可能与源码发行包目录不同，以注册项为准。

已授权保存但注册服务写入关闭时，用同一服务程序启动一次任务专用配置，而非改常驻默认开关：复制已核对配置至本地任务目录，设置 `enable_experimental_writes=true`、`allowed_write_targets={"channel":2,"scene":8,"addresses":[0,63]}`（这是格式示例，必须替换成当次授权范围）。同网关未过期的能力快照可复用；不复制实时值作为目标依据。避免同时运行常驻服务和临时客户端占用总线；任务结束关闭专用开关，默认配置保持不变。缺少真实入口/配置时才询问位置。

已完成四类请求的独立离线推演，以及0.43正式服务上的独立B0实灯预览、单场景保存、单灯调用及原值恢复。根代理随后独立核对全部64灯输出/组成员/场景15和B0参数/16场景一致。首次受限沙箱身份查询超时，关闭后经宿主网络权限澄清再执行；该证据不代表安装后全新用户会话自动发现或全部功能路径已验收。
