# 找灯、闪烁、相对调光和组操作

参数存储约束见 [参数](parameters.md)；用户要求通过上位机界面操作时改用 Computer Use Skill。

版本号表示接口引入及当时验证范围；先确认当前服务实际提供该接口。某接口未覆盖的类别需另走对应流程，不能从历史验收推断全部范围已完成。

## 单灯最大／最小亮度（0.44）

工具列表提供`dali_set_lamp_level_extreme(channel,address,extreme)`时，可用minimum或maximum调用灯具新读配置中的最小／最大亮度。最小亮度不等于关灯，最大亮度也不一定是raw254；这是一次原生极值命令，不改上下限参数，不扩为组或整通道。用户指定百分比时继续用目标准备和实时输出。当前只支持DT8、稳定且色温已知的原输出。

检查state、receipt_status、target_verified和actual：completed_readback需回执及目标读回均符合、色温保持；output_changed=false表示原本已在该档，不声称观察到了变化。回执不明只重新核对身份并读回，不重发，仍为stopped_receipt_unknown；日志故障或输出不符也不是成功。它不自动恢复，历史原值及意图可通过`dali_get_level_extreme(operation_id?)`查询，记录不代表仍有运行进程。本板B0在配置min2/max254下已通过公共MCP实测及每阶段全64背景核对，最终原关闭状态、色温4000K、全64组成员及B0参数/16场景恢复。工具分别约2.80秒/2.78秒，不含额外全板审计；其他限值组合及故障分支为模型证据。

## 有限次数闪烁

用户要求闪烁一盏灯时，用 `dali_blink_lamp(channel,address,cycles=3,period_ms=2000)`。period_ms是一整个亮灭周期；400/2000毫秒是所见上位机的出厂快/慢默认值，不代表用户当前设置。允许400～60000毫秒、100毫秒步进，1～100周期且总请求时长不超过60秒；只针对一个明确DT8短地址。服务保留稳定原亮度/色温，采用上位机原生最大亮度/关闭命令循环，结束恢复原亮度，不写场景、组或参数。未知/超过5秒恢复渐变会在控制前拒绝，不通过改渐变参数绕过。周期≥2000毫秒时逐阶段读回；更快时只记录回执与发送时刻，避免查询打乱节奏。`completed_verified_restored`才包含所有阶段样本和最终原值核对；`dispatched_restored`只证明命令序列和最终恢复，不能声称每个快闪亮灭阶段或实际闪烁频率已验证。定时延误过一半周期时停止，不补发追赶。用 `dali_get_blink(operation_id?)` 查看原值、进度和当前进程活动标记；取消用 `dali_cancel_blink(operation_id)`，随后等待worker读回恢复，cancel_requested不是已结束。失联、磁盘失败或取消后不自动重播；保持MCP进程到恢复完成，强杀无法保证收尾。`restore_unverified`先读取当前值与原记录，不盲目再闪或重发。现场验证B0慢闪2周期、快闪3周期的上述限定证据，以及原亮度200时中途取消恢复200；每轮核对其他63灯不变，最后恢复整板全关4000K、B0原参数及16场景保持。纯UI点击路径及其他灯具未验收。

## 单灯相对调光

用户要求一盏灯“调亮一点／调暗一点”、且未指定精确百分比时，可用 `dali_relative_dim(channel,address,direction="up"或"down")` 发送一次上位机同类F011命令。只作用于一个明确短地址，不扩为分组/广播，不承诺固定百分比或固定原始档差；用户指定目标百分比时仍用目标准备与绝对实时输出。服务先读稳定原值，发送一次，再独立观察亮度方向与色温。`completed_readback`表示收到相关回执且观察到稳定、方向正确、色温保持；`no_change_observed`仅表示没有观察到变化，不能报告调光成功或自动补发；`outcome_uncertain`、`unexpected_output`先检查当前值和记录，不重发。回执丢失时即使亮度变化也保留不确定。客户端失去响应后用 `dali_get_relative_dim(operation_id?)` 读取原值、发送意图和读回；记录不证明进程存活或一定已发命令，不自动重放或恢复。现场仅验证B0在4000K时raw200→209→200，两阶段其他63灯保持，最后另行恢复原全关状态；原参数及B0全部16场景未变。没有验证端点、其他速率代码或专用闪烁，也不能把该MCP验收写成Computer Use点击验收。

## 按组预览

dali_set_group_live_output 控制一个明确整组，不能把用户指定的部分成员当成整组。expected_addresses是预期完整成员，verify_addresses是其中1～8个样本；channel=1/2，group=0～15，level_raw/kelvin_raw省略即保持。服务先搜索现有地址并逐灯读取所属组，实际成员必须与预期一致，才检查DT8能力及双参数渐变并发送组命令。scope_changed或preflight_failed表示未发送控制；先检查成员差异/失败原因，不通过盲目扩大预期清单来重试。扫描可能约4分钟，成员读取非原子，当前无跨程序锁。
通道B组1的16个成员已实测：亮度单参数、色温与亮度双参数均通过；每阶段逐一读取64地址，确认目标组变化、背景保持，结束64灯全关且色温恢复测试前值。未改场景存储、组成员或地址。其他组号、异常分支及DT6拒绝目前仅离线覆盖。组亮度开启/关闭总耗时22.328/21.718秒；双参数开启/恢复25.468/25.734秒，其中完整范围预检17.937/18.015秒。包含搜索、逐灯成员读取、渐变等待及样本核对，未达到上位机直接组操作速度；不能拿这些总时间冒充纯发送耗时。按组调用已存场景见下文。

## 修改组成员与恢复

`dali_prepare_group_membership(channel,changes)` 新读明确短地址的完整16位组成员及实时输出，生成10分钟计划。每项必须包含 `address`、`add`、`remove`，后两者是0～15组号列表，不可重叠。只改列出的组位；不把“加入组15”解释成替换整份成员列表。删除在添加之前，可能有短暂成员关系空缺。

用户已明确授权该范围后，调用 `dali_apply_group_membership(plan_id,confirmation)`。单独任务配置启用 `enable_experimental_group_writes=true`，并设置 `allowed_group_write_operations=[{"channel":2,"address":0,"group":15,"member":true}]` 等精确操作列表；这是格式示例，必须对应当次授权范围，`member=false`表示移出。不能用场景写开关替代，也不改常驻默认开关。结束关闭任务开关。

计划仅尝试一次；写前备份、每步冲突检查、落盘意图后发送，再读回完整成员。`completed_readback`只证明目标范围当时的成员和原灯光符合；其他地址不在默认验收范围内。丢回执时只重新连接读状态，停止剩余写入，不自动重发或回滚。添加和移除的F095载荷状态字节观察到不同值，不能硬套“只有1成功”。

用 `dali_get_group_membership_plan(plan_id?)` 查原值、确认串、执行结果或最近10份摘要；它不等待操作锁、不访问总线。保存的writing阶段不证明进程还在运行；有执行声明但缺日志时也不能直接重试。OS锁覆盖共享同一状态目录的组控制器，不能阻止上位机、其他工具族或其他目录的客户端改设备。

用户要求恢复或原试验已明确包含恢复时，`dali_prepare_group_restore(plan_id)` 新读状态，只对能由原执行记录解释的变化生成独立恢复计划，再用恢复范围配置和返回的确认串应用。其他组位、灯光或网关发生无法解释的变化时先检查，不覆盖；恢复不是删除原始执行声明后重放计划。

现场验证限于通道B地址0：从组0/1加入组15，再移出组15，执行分别3.859/3.844秒；前后逐一核对64地址组成员与实时输出，完全恢复且全关。多地址中断、DT6及故障恢复主要为模拟验证。正式工具接口已注册，实灯试验调用同一核心执行器；接口注册不能扩大验证范围。

## 按组调用已存场景

`dali_recall_group_scene(channel,group,scene,expected_addresses,verify_addresses)` 只调用一个完整组，group和scene均原编号0～15。expected_addresses必须是预期完整成员，verify_addresses为其中1～8灯；不能把用户指定的部分成员扩大成全组。服务新搜索地址、重建同身份会话再读取全部成员；实际成员不同返回scope_changed且不调用。每成员保留原实时值、场景值及已知短渐变证据。搜索可约4分钟，保持stdio会话；当前无跨程序锁，成员检查不是原子快照。

只发一次组场景命令，未知回执后重新核对身份并仅做读回，不重新调用。分别检查receipt_status、verification_status、samples_verified及verified_sample_count；stopped_receipt_unknown即使读回符合也不能报告“干净成功”。MASK分量须保持调用前值；全部MASK样本不能证明调用效果。样本验证不是全部成员或非成员验证，不能声称背景已经核查；需要整板验收时另读明确的全部地址。

`dali_get_group_recall()`列最近10个记录，传operation_id取原值、pending和结果，不等待总线锁、不连设备、不重播。中间阶段不证明进程存活。没有自动回滚；用户要求恢复时先读实际值，按记录中的明确地址和分量用实时接口恢复，不调用另一个场景冒充原值。参数存储范围见 [参数流程](parameters.md) 的当前字段与限制；源码中的其他候选计划不是现场写入授权。

0.10按组场景现场验收：通道B组1的16成员调用现有场景6，实际F093载荷0202010000000000，只发送一次；3个样本通过，另独立读取全部64地址确认仅16目标为raw254/4000K、背景48灯未变。恢复后再次读取64地址，全关且原始亮度/色温与基线完全一致。没有写场景、组成员或参数。工具总耗时42.844秒，预检39.156秒，发送及回执0.032秒；不将发送时间冒充工具总时长。其他组号和失败分支仅模拟覆盖。
