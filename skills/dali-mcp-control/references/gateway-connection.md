# 网关搜索与项目连接（0.40起支持，0.41修正名称解析）

仅在实际工具列表包含以下入口时使用；旧版 `dali_discover` 只向配置 IP 单播查询，不能称为局域网搜索。

换项目先搜索当前网络，不沿用上一个项目的固定IP或默认网关名。0.41按名称结束符解析固件与MAC，并按上位机的GBK编码读取名称；0.40在名称长度不同于默认值时可能识别错误，跨项目使用应升级到0.41。name_decode_valid=false表示名称含无法解码的字节，保留原始name_raw_hex，不以损坏的显示名称判定身份；核对MAC及项目网段。

新项目不知道 IP 时先调用 `dali_list_network_interfaces`，按项目接线选择 NIC；不明确且用户要求搜索本机局域网时可省略 local_ips 搜索所有可用 IPv4 广播接口。`dali_search_gateways(local_ips?,timeout_seconds=2)` 返回名称、IP、MAC、固件、回包网卡与 search_id/candidate_id；不需要先填网关 IP。广播不保证穿过路由器/VLAN，某网卡失败保留 partial，未发现不等于网关已离线。

搜索ID只属于创建它的MCP服务进程，搜索→选择→依赖当前选择的读取必须保持同一服务会话。不要用每次新开服务的client.py，把上一次搜索ID交给下一次调用。

按用户已给的名称、MAC、项目网段选择结果；只有一台且符合任务时可直接选择，不重复请求许可。多个无法区分的目标需要用户确认具体哪一台。调用 `dali_select_gateway(search_id,candidate_id)`，服务独立复核身份并握手。搜索结果5分钟过期；冲突或身份变化重新查询，不编辑候选对象绕过检查。未知固件可以展示搜索结果，当前仅允许已验证1.6.9进入控制，不能把“被发现”说成“全部功能兼容”。

成功后现有查询/调光/场景工具使用选定目标。`dali_get_gateway_selection`只反映本地选择，不证明仍在线。切换时原任务必须结束，禁止为了切换强制杀掉仍在执行的保存/找灯/寻址任务；忙时查询该任务。网关状态目录按身份隔离，回到同一身份时保留本会话已知的原状态目录。同身份换IP后重新搜索、选择，能力缓存仍按IP/身份匹配，旧写入计划须重新核对。

选择会关闭此前所有存储写权限，不把其他项目的上位机缓存文件绑定带过去。选定结果含新的config_path，供后续已授权任务配置/下次启动使用；配置文件可被加载不代表当前常驻进程已重读它。仍沿现有任务配置和会话生命周期管理写入，任务原值和恢复证据必须保留。

当前证据：独立搜索模块在本测试LAN一次广播找到网关并完成单播身份复核/握手；标准SDK模拟验证无IP启动、两个网关切换、记录隔离、同身份换IP、写门清除、忙时拒绝切换。标准MCP真实LAN已完成空配置启动→网卡枚举→搜索→选定连接→原有工具读取B0/B63闭环，输出均为关闭4000K，会话已关闭，未发送灯具控制或存储写入命令。另一实体网关、跨路由广播、其他固件及新安装会话尚未实测。

## 单次命令行客户端

没有持久MCP连接时，用包内mcp/gateway_client.py：先不带--connect-mac搜索，查看输出；确定身份后，用新的输出文件加--connect-mac重新搜索并在同一次会话选定。需要限制网卡时传--local-ip，可重复指定。它只搜索/握手、不提供灯具控制。

```text
python mcp/gateway_client.py --config project-connection/config.json --output search.json
python mcp/gateway_client.py --config project-connection/config.json --connect-mac 02:00:00:00:00:11 --output connection.json
```

示例MAC须换成实际目标；配置文件可以不存在，输出文件必须新建。成功结果的config_path才是后续client.py或新MCP进程应加载的连接配置；bootstrap路径不自动改写。未唯一发现目标时停止，保留搜索结果；需要时缩小到明确网卡，不凭同名或固件兼容性猜选目标。已运行的后台任务仍须结束后才能另开连接。

独立Skill模型试用先遇到两个同名Site-B并正确停止，补充明确MAC后完成B→A→B及两处B0读取；据此补充本节会话边界。专用CLI另以三个SDK进程验证“搜索→按MAC重新搜索并选择→加载新配置读取”，以及目标缺失与旧证据保护；实际CLI也已在当前LAN按MAC重新搜索、连接并导出配置，新SDK会话成功加载该配置读取灯具。

2026-11-15实体补验：上位机将已知网关临时改为中文短名“测试B”，关闭上位机后，正式0.41客户端从不存在的配置启动，不传网关IP或本机IP，搜索3个接口，正确解析GBK名称、DALI MAC和固件并完成连接。再由上位机恢复原名，独立MCP再次搜索、连接确认恢复，两个会话均正常关闭。31字节名仍仅为合成报文验证；另一实体网关、实际换IP、跨VLAN和其他固件仍待现场验证。新项目不需要改网关名称，这只是兼容性验收。
