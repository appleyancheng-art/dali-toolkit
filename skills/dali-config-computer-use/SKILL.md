# DALI 上位机界面操作

## 单灯调光曲线保存与恢复

在本版PC1.2.4.1，先选择明确通道和短地址并完成“读取信息”。单灯页右下DT8设置区的对数／线性单选对应曲线，旁边“保存设置”与顶部“保存所有参数”不同；本次DT8类型下拉框禁用且未修改，选择曲线后点击该区保存一次，再完整读取信息确认。让按钮完整可见，用当前控件与截图定位，不照搬旧索引或只凭保存成功提示判断到位。点击后没有提示时先完整读取，若已是目标则不再保存。

本板B0已通过独立UI对数→线性→对数保存、重新读取及正常退出；两阶段另用只读MCP核对曲线0→1→0，其他B0已支持参数/16场景、全64输出/组成员保持，全关4000K。该结果证明本板此路径的存储值变化范围，不证明按钮在其他类型下的全部发包范围或线性光学响应。执行者使用了现有Skill，父代理核对范围及后置审计分别留证。

切换曲线会重算现有原始亮度的百分比标签，如raw2从约0.1%显示为0.8%，不代表这些参数或场景已写入；不要为恢复百分比显示而另存场景。通过UI或其他客户端改过曲线后，后续MCP百分比编排先刷新能力缓存；现有MCP非零百分比只支持已确认对数曲线，线性时应报告限制，不套用对数公式。

## 快速测试按钮的实际输出核对

单灯页的最大／最小亮度、调亮／调暗按钮操作后，用批量场景窗口的“刷新实时状态”核对实际输出；上方编辑滑块可能仍是旧值。保持“操作实时输出”关闭，刷新结束后可只读打开目标行的“设置”浮层查看原始亮度，不移动滑块、不保存场景。低亮度的一位小数百分比不足以判断是否变化：本板B0由raw2调亮到raw11，表格均显示0.1%。极值依据该灯当前配置，最小不等于关灯、最大不一定为raw254。

刷新某一已有组只查询该组显示的灯，不证明组外状态；必要时按任务范围另核对。读取期间失去窗口捕获时重新选择当前窗口，不能把捕获失败解释成控制失败而重复点击控制按钮。

0.44独立界面试用已在本板B0逐阶段刷新确认最大显示100.0%、最小raw2、调亮2→11、调暗11→2，均显示4000K；随后通过单灯关闭及实时刷新恢复0.0%/4000K，断开退出。最大阶段未打开原始值浮层。根代理在退出后另用只读MCP核对全部64输出/组成员及B0参数/16场景与基线一致；不将后置审计算作每个UI阶段的全板证据。仅刷新也可能产生未保存草稿提示，只丢弃本轮刷新产生的草稿，保留用户原有未保存编辑；不能把草稿提示当作设备场景已写入。

## 新项目的网关入口

用户指定操作上位机时，仍通过本Skill的网卡选择、搜索网关和连接流程执行；不要把旧项目IP当固定前提，也不静默改走MCP。用户要直接通信时，MCP0.40已提供局域网搜索和选定连接，由dali-mcp-control处理；跨项目使用0.41及以后版本，以正确解析变长GBK名称。MCP搜索成功不等于上位机当前已连接，反之亦然。

网关名称编辑（PC1.2.4.1实测）：先连接，再从网关右键“打开网关”进入设置。名称框须点击聚焦、全选后通过type_text实际输入；本次set_value虽改变可见文字且保存提示“保存完毕”，重新搜索仍为旧名，静态核查显示保存依赖该框的isModified。实际键入已完成中文短名“测试B”保存及原名恢复，均由关闭上位机后的独立MCP搜索、握手核验。保持IP、网关地址、掩码原值，不能以保存提示代替独立读回；此差异仅针对本版名称框，不外推全部控件。设置对话框可能在确认保存提示后自动关闭，先重新枚举窗口，不重复点击失效窗口。新项目搜索不需要改名。

## 分阶段工程恢复后的界面复核（0.37）

新MCP协调任务先恢复设备参数/场景/组成员，再一次提交所选本地名称与平面图；它需要上位机关闭。用户指定直接界面操作时仍走本Skill，不用MCP代替。协调任务返回完成只证明所选数据在读回时一致，未证明UI显示。后续用既有启动路径打开上位机，选正确网卡、连接并搜索现有地址，再逐项核对选定灯名/组名/组内场景备注、底图与标记；需要时点适应窗口，不将扫描或画布显示算作参数/场景的独立总线读回。

任务partial时先查阶段和子任务证据，不能直接重开上位机后宣称完成，也不能用UI补写全部工程掩盖失败。协调撤回只恢复其实际尝试项，保留无关缓存刷新字段；撤回后需第二次重启核对原显示。0.37已完成本板B0最小联合往返：渐变时间4→5→4、场景15从MASK改为raw200/4000K后恢复、组15加入后移出；同时恢复并撤回三个本地名称和单一底图标记。两个阶段各自读回通过，完整重启上位机确认新名称/底图，再撤回并第二次完整重启确认默认名称/空画布。最终独立核对B0全部已支持参数和16场景、64灯地址/成员/输出与基线一致，全关4000K。保留正常界面缓存刷新字段和原图片；新增PNG保留为未引用证据。大范围及异常/取消仍以模拟测试为证据，不外推为全板实体工程验收或真实灯位核对。

## 工程名称来源核对（0.36）

MCP可把灯名、组名、组内场景备注附加到可移交工程，再通过独立本地文件事务恢复。用户指定直接界面操作时仍用本Skill；MCP文件恢复完成后，按下述重启/正确网卡/搜索现有地址流程核对所选名称。附件只保存本地名称，不是实灯或场景参数读回；源缺失名称可能按明确选择清空当前标签。0.36新增接口只在工作区副本完成两SDK会话往返，不将旧版同名文件机制的UI证据写成该新来源的现场UI验收。

## 0.35：改址后的标签和灯位核对

0.35 doc1已补显示验收：关闭上位机时临时加载先前MCP实测产生的迁移文件，完整重启并搜索网关，平面图适应窗口后显示通道2地址63和保留的通道1地址7；连接并搜索通道2现有地址后，树显示A0默认名、A63附带迁移名称。退出后限定撤回临时名称/平面图字段，保留扫描刷新字段，再完整重启确认空画布及A0/A63默认名。此轮未重做实体改址，测试坐标不能证明物理灯位；这是文件输出的UI加载验收。不要为普通调试复制此临时夹具流程；实际迁移仍须绑定当前总线映射并按用户范围执行。

MCP已提供改址记录绑定的灯名/灯位文件迁移及条件恢复，网格布局则另建新版本；这些操作不更新原生参数或组成员缓存。完成文件迁移后，按已验证启动路径重开上位机，核对目标地址灯名、原地址标签清空及平面图标记的地址/位置，必要时适应窗口。不要把MCP文件读回写成“界面已验证”，也不要把缓存行或灯位标记当成当前在线灯具；是否重新连接、搜索或刷新仍按本次任务范围执行。用户明确要界面操作时继续使用Computer Use，不静默替换成MCP。

## 地址管理的显示与执行边界

0.34新增的是MCP单灯改到空闲地址及条件恢复，底层B0→63→0已实板验证；这不等于本Skill完成了上位机改址按钮的界面验收。用户明确要求界面操作时继续走Computer Use，不静默改用MCP。MCP改址前要求上位机关闭；完成后需要重新搜索设备并按实灯核对名称/平面图，旧本地映射不会自动迁移。全64地址占满时不为普通改址自行删除另一灯地址或启动全通道重新分配。

PC1.2.4.1发布对象静态核查发现，BatchModifyAddress的“搜索”处理调用loadDemoData，“批量修改”处理生成swap步骤并显示“交换步骤”提示框；这些路径尚未完成界面实测，未找到其中直接下发设备交换命令的证据。不要把该窗口的“搜索完成”或步骤列表当作真实总线搜索、设备改址成功。单灯改址是另一条有明确封包/回执的路径，必须按独立范围及读回确认。当前64地址全占用，不能直接将一盏灯改为另一盏的已有地址。

## 0.32：核对从工程恢复的平面图

文件事务完成后重新启动上位机，选择正确网卡、搜索网关，网关右键→平面图标注→适应窗口。本次PC1.2.4.1在未连接网关、未搜索灯具时，已能加载指定底图及通道2地址0标记，左侧地址列表为空不表示已保存标记丢失。采集范围恢复只显示B0，没有带入来源中的B1；图上“2 A0”中的2是通道，A0标签不能推断通道A。文件操作与界面显示分别核对，不用本地标记声称设备在线或物理位置正确。

本次通过MCP撤回后再次重启、打开平面图并适应窗口，确认恢复为空画布。试验全程未连接DALI会话、未搜索或控制灯具；原生退出刷新内容保留，新PNG按文件事务约定保留为未引用证据。已有底图替换、范围外全部标记和图片冲突为模拟测试范围，不能说都已实际UI验收。

新窗口若只取得文字状态后点击报 `coordinate input geometry is unavailable`，重新选择当前窗口并取得带截图的状态，再依据新观察重试一次。不能把异常当作点击已完成，也不要沿用旧窗口索引。

## 平面图标注（0.31 开发验证）

网关右键→平面图标注可在未连接时打开，但本轮启动未搜索地址时列表为空；连接并搜索现有地址后，列表按通道显示地址。导入底图后，从列表把指定地址拖到画布，核对标记的通道与地址，再点平面图窗口内的“保存”。此保存是本地底图和位置，不是场景存储或灯具控制。PC1.2.4.1已用临时640×480底图完成通道2地址0、1的拖入、保存及关闭窗口后重开；重新打开时底图可能缩得很小，先点“适应窗口”再判断是否丢失，两个标记均正常恢复。本次没有验证整应用重启、移位撤销/重做、删除或导出图片。

底图路径输入可能首轮没有实际进入文件名；观察文件名值，必要时Alt+N重新定位后输入，确认完整路径后才打开。已保存位置为底图宽高比例，不能把屏幕坐标直接作为原生文件坐标。退出上位机会刷新地址缓存和lastSeen；另一条文件恢复路线应限定本轮平面图字段并保留其余最新字段，不能因整个文件发生正常变化就盲目覆盖旧备份。本次试验已撤回平面图并清理本轮底图副本；全板独立读回全关4000K、原参数/场景/分组保持。

## 启动接口超时的已验证备用路径（0.30 doc1）

先用当前提供方查询应用与窗口。正常launch调用超时后，重新列窗口并核对进程，不能因超时就断言应用已退出或重复启动实例。本机曾发生按安装应用ID、已核对EXE路径启动均超时，但通过已有文件资源管理器窗口双击同一预先存在的程序成功。

无ConfigMaster窗口或进程时，可选择唯一的当前资源管理器窗口，以Alt+D定位地址栏、观察焦点后输入已核对的程序所在文件夹路径，Return导航；刷新并确认该目录中应用程序文件，再双击该文件。只输入文件夹路径，不经资源管理器执行终端命令，不使用运行对话框，不绕过安全或权限提示。随后重新列窗口，选唯一的DALI Config Tool主窗口；不能沿用资源管理器句柄或旧上位机索引。该备用路径已实际启动PC1.2.4.1并完成连接与名称复查，不代表启动API本身已修复。

Qt菜单、树节点和对话框可能在两次调用之间失去可访问索引。出现element not available时刷新观察；若新索引仍不稳定，使用最新截图中已确认的坐标执行一个动作再刷新。不同窗口/弹窗截图坐标不得混用。界面刚切换时树可能落后一帧，以重新观察后相符的状态为准。

## 原生本地工程导入的已验证路径

若应用已退出，按用户已有授权通过当前Computer Use提供方启动已发现的安装入口或已核对程序路径，再重新选择唯一窗口。启动报超时先查新窗口，按提供方恢复规则处理，不反复启动多个实例。启动后可能默认错误网卡；选择测试网关所在网卡、搜索并连接网关，选正确通道搜索现有地址。PC1.2.4.1即使仅导入本地配置，也要求已搜到在线地址。

网关右键→导入网关数据→导入数据，是仅本地导入；“下发参数”会写设备，是另一条操作。先保存本地配置恢复依据，选择明确的Excel文件。文件对话框可能被包含在主窗口的截图和树中，list_windows不单独列出它；不能编造窗口句柄。索引报not available时重新观察，优先当前截图坐标聚焦文件名或Alt+N。当前提供方有焦点字段误报搜索框的情况；需要观察文件名的插入光标，并在输入后确认文件名Value和可见路径正确，才点击打开。若仍不能确认，停止提交。

导入确认界面明确普通参数空白保持、场景分量空白MASK、ECG场景优先、名称按指定源表且空名称清除。按已有用户授权执行，核对完成提示及目标页，不把本地显示当实灯读回。实际样本已完成64参数/1024单灯场景导入、B0本地显示及两份缓存的独立核对，之后退出应用并精确恢复试验前文件；未点击下发参数。Excel的0.1%实际导入为raw1，无法精确保留原先raw2。名称变更/空白清除、普通参数空白、场景冲突和原生设备下发仍待分别验收。

本路线通过真实界面操作，不调用 DALI MCP 代替点击。依赖可用的 Windows Computer Use；本机已验证提供方为 computer-use 技能的 node_repl + @oai/sky。开始操作前读取当前提供方技能及所需 API/操作规则，不复制历史窗口句柄或索引。

## 定位与范围

- 用当前窗口清单定位进程 ConfigMaster.exe、主标题 DALI Config Tool。批量场景窗口标题可能只有 ConfigMaster；网关设置、平面图和进度弹窗可能是独立窗口。
- 最小化窗口先激活并重新取得窗口对象。每次观察后执行一个动作，再刷新；Qt 树和截图不一致时重新观察。用当前语义控件定位，必要时使用当前截图坐标。
- 明确所选网关、通道、单灯/分组/广播以及页面标题。树中高亮项与右侧页面不一致时不要执行控制。地址 0～63、场景 0～15直接使用显示编号，不加减一。
- 当前版本在通道2树和表格中也显示 A0、A1 等标签，不能凭 A 前缀推断通道1。批量窗口可能默认回到通道1，即使入口来自通道2节点；每次重新核对通道下拉框。
- Qt通道下拉列表展开时，截图可能失败或语义选项点击报命中所属弹窗而非目标窗口。已验证替代路径：点击当前可访问组合框，观察焦点和选项后用方向键选择、Return提交，再核对截图中的通道和表格。方向键未提交时树中Value可能仍是旧通道；不能据此连发方向键。每一步仍须重新观察，不能复用历史坐标。
- 切勿把初始表格或缓存当作设备实时值；“读取信息/读取当前页参数”完成后才能把值记为总线读回。

## 已知界面路径

设备树相关节点右键可见：打开网关、连接、断开连接、批量场景配置、平面图标注、导出网关数据、导入网关数据。菜单随节点和版本变化，以当前观察为准。

批量场景按通道 → 组 → 场景号选择，先看清当前页包含的地址。每个灯的同号场景跨组共享，不同组不是独立存储空间。

## 预览与保存

1. 用户要求先看效果时，进入“操作实时输出”模式；按钮红色表示激活，此时读取/保存等按钮通常变灰。编辑参数会发实时命令，进入后不要试探性拖滑块。
2. “刷新实时状态”查询当前输出；“测试场景效果”调用当前组已存场景；普通模式草稿修改只改草稿。不要用测试场景来展示未保存草稿。
   同时改变色温和亮度时，先调色温并让渐变完成，再调亮度；连续拖动两种滑块可能打断色温渐变。当前界面中刷新按钮在实时模式下不可用时，先退出实时模式、刷新核对色温已到目标，再进入实时模式调亮度。表格目标值变化不能代替实时读回。等待时间需依据该灯已读出的渐变参数，不硬套别的测试灯。
3. 用户要求保存时，先记录认可的目标值和目标地址，退出实时输出模式。现场观察：刷新实时状态会把表格中的 MASK 改成实际色温，随后编辑可能把这些背景格也标成待保存。应重新“读取当前页参数”恢复存储原值，再仅重建授权目标的草稿，核对所有黄格；不要直接保存刷新后产生的整页附带变化。读取会替换临时草稿，所以先留存目标。

5. 等待进度结束，再从总线读取核对。没有出现错误不等于保存成功；界面回执也不是全部物理效果的证明。
